Contract review on a synthetic data room

Simulation · synthetic contracts

Six contracts, five questions. Every answer points to the clause it came from.

The interactive grid needs JavaScript. The four steps behind it are described below.

How a review agent like this works

In a deal: the data room opens, the grid fills overnight, and the red-flag memo is on the partner's desk before the first call.

  1. 01

    Ingest

    An orchestrator routes each task: a strong model for the hard reasoning, a cheap one for routine steps. So cost stays low and every document is read.

    Illustrative code 
    type Task = { kind: "extract" | "classify" | "reason"; doc: string };
const route = (t: Task) =>
  t.kind === "reason" ? STRONG_MODEL : CHEAP_MODEL;

for (const doc of dataRoom.files) {
  queue.push({ kind: "classify", doc: doc.id });
}
  2. 02

    Vectorise

    A vectorizer splits each document clause by clause and indexes it for retrieval. So a question finds the clause, not just the file.

    Illustrative code 
    const clauses = splitByClause(doc.text);
for (const c of clauses) {
  await db.insert("clauses", {
    doc_id: doc.id, ref: c.ref, text: c.text,
    embedding: await embed(c.text),
  });
}
  3. 03

    Retrieve & draft

    For each question, the closest clauses are retrieved and the answer is drafted from them alone. So nothing comes from memory.

    Illustrative code 
    SELECT ref, text
FROM clauses
WHERE doc_id = $1
ORDER BY embedding <=> $2
LIMIT 5;
  4. 04

    Verify

    Every answer carries its clause reference and quote, and the lawyer signs off. So the check takes seconds, and responsibility stays with the lawyer.

    Illustrative code 
    const ok = answer.quote !== null
  && sourceText.includes(answer.quote);
if (!ok) answer.status = "needs-review";
